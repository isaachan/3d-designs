## 版本目录规约（从v5开始）

从v5开始，每个版本都按下列职责组织文件。新建v6、v7及后续版本时，必须沿用这些目录名称和用途；新增目录须在对应版本的README中说明职责。
本README维护版本导航和通用规约，具体版本的设计变更统一记录在该版本的`CHANGELOG.md`中，例如[v5/CHANGELOG.md](v5/CHANGELOG.md)。

下表路径均相对于各版本根目录（如`v5/`、`v6/`）：

| 文件或目录 | 用途与约定 |
|---|---|
| `README.md` | 版本入口：说明设计概况、正式CAD、文档与打印文件入口，以及常用命令。 |
| `PROJECT_STATUS.md` | 当前状态：记录已完成事项、验证结论、待验证问题和下一步工作。 |
| `CHANGELOG.md` | 设计与维护沿革：按日期记录变更及影响；同一事件已有记录时补充原条目，不重复新增。 |
| `cad/` | 正式总装CAD及模型规范；总装用于整体和接口验证，各组件索引明确唯一源文件。 |
| `cad/main/` | 主体CAD入口，包括两块广告牌的固定结构，不含可换文字载板。 |
| `cad/sign-carriers/` | 上方、右侧文字载板的源文件索引及新增定制款。 |
| `cad/parking-inserts/` | 通用底脚和车型卡槽的源文件索引及新增车型款。 |
| `src/garage_bookshelf/` | 可复用的建模、外观、验证、导出和打印逻辑，供工具共用。 |
| `tools/` | 验证、导出、渲染、排盘和打包等命令入口；一次性迁移脚本须注明用途及执行状态。 |
| `tests/` | 工具与工作流程检查，验证输出路径、文件保护和数据一致性等约束。 |
| `pyproject.toml` | Python工具包配置，与`src/`、`tools/`和`tests/`配套维护。 |
| `assets/` | 建模和打印所依赖的固定输入资源，如冻结字形、打印预设；生成工具不得覆写这些输入。 |
| `docs/` | 维护者通过`maintenance.md`修改和生成，组装者通过`assembly.md`、`customization.md`拼装和提出定制需求；设计与接口规范共同引用。 |
| `docs/interfaces/` | 文字载板与车型卡槽的唯一接口和验证规范；车型卡槽沿用指定的层板＋托座试件方法。 |
| `printing/` | 当前文件入口、排盘计划和带哈希的组件清单；直接分为以下三类，不设current或日期交付层。 |
| `printing/main/` | 主体打印文件及单独标明的个人设置；不含可换文字载板和车型卡槽。 |
| `printing/sign-carriers/` | 按上方／右侧及款式保存文字载板，说明接口版本和试装状态。 |
| `printing/parking-inserts/` | 按车型及修订保存卡槽，说明适用车型、打印设置和试配状态。 |
| `studies/` | 结构分析、车型适配和配合试件；每项研究独立保存说明、输入与结论，验证后再决定是否并入正式设计。 |
| `build/` | 可再生成的导出、预览、切片、日志及候选交付包，按`build/<run-id>/`分次输出；临时文件放`build/tmp/`。除目录说明外不纳入Git。 |
| `archive/` | 历史CAD、旧方案、旧工具、快照和报告；保留原始来源与验证结论，不作为当前设计或打印入口。 |

维护及新建版本时还必须遵守：

1. 版本根目录只放入口文档和项目配置，模型、脚本、打印文件、研究资料与生成结果分别归入上述目录。
2. 新版本的正式CAD、工具和输出路径必须指向本版本；不得由新版本工具改写旧版本目录或历史归档。
3. 自动生成和打包先写入新的`build/<run-id>/`，不得覆盖已有结果或人工3MF；确认交付后按组件保存到`printing/`，更新文件清单、源CAD哈希、打印参数和验证记录；旧交付完整归档。
4. 研究试件与正式交付分开保存；历史验证保留当时的源版本和结论，不得直接当作当前设计的验证结果。
5. 设计或打印交付变更时，同步更新本版本的`README.md`、`PROJECT_STATUS.md`及相关`docs/`、打印说明，并在`CHANGELOG.md`记录变更；本总览不追加逐日变更流水。
6. 新增文字或车型通常只增加独立定制款；接口不兼容时必须建立新接口版本，注明兼容主体。组装者与维护者共用接口规范，不重复维护两套尺寸和检查规则。
