# 车型卡槽规范：实测四轮弧形槽

所有车型卡槽必须遵循[BMW Z4 E89设计方法](../../studies/measured-tray-s51-b23-d10-t5p1/README.md)。原生建模和验证以[build_tray.py](../../studies/measured-tray-s51-b23-d10-t5p1/build_tray.py)为实现参考，[validation.json](../../studies/measured-tray-s51-b23-d10-t5p1/validation.json)记录该参考件的检查结果。

设计流程为：实测轮胎数据 → 推导轴距和轮距 → 在通用底脚上建立四个弧形轮槽 → 验证轮胎净空和十个车位 → 生成单托座打印项目 → 实物试配。新增车型使用自己的实测值，不能沿用参考车的数值或凭车身外观估计轮胎位置。

主体凹槽属于主体；通用底脚、取放耳和车型轮槽属于`parking-inserts`。通用底脚接口标识仍为`parking-base-v1`。

## 测量输入与推导

单位均为mm，必须记录测量定义和原始实测值：

| 输入 | 定义 | BMW参考值 |
|---|---|---:|
| `S` | 同侧前轮最前缘至后轮最后缘的前后跨度 | 51 |
| `Bf` / `Br` | 前／后轴左右轮胎外侧之间的总宽度 | 28 / 28 |
| `Df` / `Dr` | 前／后轮胎直径 | 10 / 10 |
| `Tf` / `Tr` | 前／后轮胎宽度 | 5.1 / 5.1 |

轴距`Wheelbase = S - (Df + Dr) / 2`；前轮距`FrontTrack = Bf - Tf`，后轮距`RearTrack = Br - Tr`。轮心横向坐标分别为`±FrontTrack/2`、`±RearTrack/2`，纵向坐标为`±Wheelbase/2`。参考件的轴距为41mm，前后轮距均为22.9mm。

这组输入按每轴左右轮胎同尺寸处理；若实际车模不符合，应补充左右独立实测和相应参数，不能用猜测值掩盖差异。车身、底盘、轮拱和最高点的净空另外实测；理论轮胎圆柱不能替代实际车身验证。

## 通用底脚与四轮槽

1. 参照BMW脚本在独立FreeCAD文档中原生重建通用底脚：40×80×2mm、圆角R2；取放耳宽10mm、前伸3mm、耳上凸起1.2mm。`DesignParameters`控制这些接口参数。
2. 新底脚与正式总装的`parking_tray_interface_Body`做双向布尔差比较，两侧差体积均小于0.000001mm³；保留取放耳及接口，不修改主体来迁就车型。
3. `WheelFit`保存七项实测值和配合参数，通过表达式推导轮心位置。用全约束草图、原生Pad建立四个轮槽块，再以YZ平面的圆形轮廓、沿轮轴方向的Pocket切出弧形承托槽；不得用静态形状或导入网格代替可编辑特征。
4. BMW参考配合参数为每侧胎宽间隙0.2mm、径向余量0.15mm、侧壁厚1.2mm、槽高出底板1.6mm、槽块前后长10mm。槽内宽为对应胎宽＋两侧间隙；弧半径为对应胎径/2＋径向余量，弧底与底板上表面相切。新车型调整余量时记录依据，并重新验证和试配。
5. 四轮槽采用重力落座，向上即可取车；保持参考方法的承托与低挡结构，不压胎、不增加未经验证的弹性扣或向下锁止。新增结构超出该方法时需要独立说明与验证。

参考件总包络40×83×3.6mm，其中底脚与取放耳接口固定，车型上部结构的尺寸由实际测量和配合参数确定，不能通过缩放整个托座适配另一辆车。

## 原生CAD与几何验证

- 全部草图完全约束，最终几何有效且为单实体。保存后重开CAD并重算，形状与体积保持一致。
- 像BMW脚本一样修改测量输入、检查派生值与几何有效性，再恢复输入，确认原形状与体积恢复；不能只交付一个不可调的形状快照。
- 在四个实测轮心位置放置与胎径、胎宽对应的理论轮胎圆柱。检查落座及向上抬起2mm时，与托座交集体积均小于0.000001mm³；同时记录实际车身和底盘净空的验证范围。
- 使用当前正式CAD中的全部承接位置，按实际布局和高度检查四层共十个车位，最终托座与各层主体的干涉体积均小于0.001mm³。正式总装及其他打印项目不得被生成过程改写。
- STL沿用BMW脚本的`LinearDeflection=0.015`、`AngularDeflection=0.08`、`Relative=False`。重开后检查封闭、无非流形、单连通；网格与CAD的体积相对误差小于0.001（0.1%）。

历史通用底脚试件只说明底脚与车位的配合，不能替代上述实测四轮建模与最终车型验证。

## 车型标记

沿用参考件的参数化标记方法：`ModelLabel`保存文字、字高、凸起高度和位置，冻结字体轮廓后用全约束草图与原生Pad生成。参考件为单行BMW Z4 E89、约4mm字高、0.4mm凸起，在0.20mm层高下为两层。

新车型更换文字和轮廓，检查标记不侵入四个轮槽、安装接口或车辆空间。文字和凸起高度改变后重新检查、切片；CAD预览轮廓线仅用于显示，不代表第二种耗材或附加几何。

## 单件打印与交付

沿用BMW方法，单件项目为一个托座、一个对象、一盘，不含层板或车模。底脚平放，X2D、0.4mm喷嘴、黑色PLA、纹理PEI、0.20mm层高、4圈墙、25%填充、4mm自动brim、无支撑。

保存3MF后检查实际排盘尺寸与最终CAD一致，各方向误差小于0.002mm；独立重新打开切片，确认一盘、一对象、无模型警告，保留实际设置、时间和用料。不能以导出成功代替重开切片检查，不交付G-code。

每款保存七项实测值和测量定义、配合参数、原生CAD、STL、3MF、预览、参数往返检查、四轮净空、十车位干涉、文件哈希和实物试配状态。新源文件放`cad/parking-inserts/<车型>/<修订>/`，打印交付放`printing/parking-inserts/<车型>/<修订>/`；既有BMW源文件保持[CAD索引](../../cad/parking-inserts/README.md)所指的唯一位置。

按[证据存放规约](../../../README.md#当前交付的证据存放规约)将当前款式的原始日志、冻结打印配置和检查用STL放在打印款式的`evidence/`，验证报告与切片结果放款式根目录，报告的`artifact_locations`关联实际文件位置。组件索引维护完整车型、修订及验证入口；详细试配结论记在款式说明。仅新增车型或修订时，不向版本README或PROJECT_STATUS复制款式清单。

在`v5/`复现参考方法，使用尚未存在的新输出目录：

```sh
/Applications/FreeCAD.app/Contents/Resources/bin/python studies/measured-tray-s51-b23-d10-t5p1/build_tray.py --output build/bmw-z4-e89-r1
```

新增车型需在独立款式的生成入口中替换实测值、车型标记和输出标识，保留BMW方法的原生建模与全部验证；原BMW参考件不被覆盖。切片和几何通过后，仍由组装者用实际车模确认落座、取放与固定效果。

BMW无字B28版已有用户实物尺寸确认；当前0.4mm凸字版尚未打印。这两种实物状态分别记录，不把旧版反馈自动当作新版已试配。
